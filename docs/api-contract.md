# API contract: Todo demo

The frontend and backend use this shared contract. Changes require coordination between the two workstreams.

- `GET /api/tasks` returns HTTP 200 and `{ "tasks": [Task] }`.
- `POST /api/tasks` accepts `{ "title": "..." }` and returns HTTP 201 and a `Task`. Titles are trimmed, required, and at most 120 characters.
- `PATCH /api/tasks/{id}` accepts `{ "completed": true }` (a boolean) and returns HTTP 200 and the updated `Task`.
- `Task`: `{ "id": "string", "title": "string", "completed": false }`. `id` is generated by the backend and remains stable while it runs.
- Validation failures return HTTP 422. An unknown task ID returns HTTP 404. Errors use `{ "detail": "human-readable text" }`.
- State is stored in memory and resets when the server restarts.
- During development the frontend may use a contract-compatible mock. A Vite `/api` proxy forwards to `http://127.0.0.1:8000`; production deployment is outside this demo.

## End-to-end acceptance

The user can load tasks, add a title, and mark a task complete. Loading, empty, and error states are visible. The frontend must not mark a failed write as successful. Backend and frontend checks run independently; integration checks use the real API.
